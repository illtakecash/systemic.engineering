# systemic.engineering

> A shared memory and coordination workspace for people and their AI collaborators studying—and practicing—socio-technical systems engineering.

**Status:** experimental, invite-only infrastructure. Nothing here constitutes adopted group governance merely because it appears in Git. The group decides what to adopt.

## Why this exists

Conversation is high-bandwidth but low-retention. Decisions evaporate, questions recur, expertise remains invisible, and opportunities die between meetings. This repository makes the group's working state inspectable without appointing a permanent secretary. It is not a replacement for relationships, deliberation, or judgment.

The repo is both a practical workspace and an observable record of how collective coordination evolves. We want to learn what helps, what ossifies, and what participants actually use.

## Operating model

**Issues = working attention.** Create an issue for new business, a question requiring attention, or an opportunity with an actionable next step. Search first. One issue should have one primary outcome and link related issues.

**Pull requests = proposed durable changes.** Use a PR for substantive edits to records, templates, or protocols. Explain what changed and why; invite affected people to review. A merge is a Git event, **not automatically a vote**.

**Markdown = institutional memory.** Archive conclusions, context, alternatives, uncertainty, and provenance in versioned files. Avoid maintaining parallel status trackers when an Issue already owns the status.

**Git history = trace, not truth.** Commits show what was recorded and by whom; they do not prove a claim, establish consent, or make an interpretation authoritative.

## Minimum contribution workflow

1. Search existing issues and files before creating a duplicate.
2. Choose the appropriate area; use a template where available.
3. State the question, proposal, or observation; cite the source or meeting.
4. Identify the contributor. If AI-assisted, disclose the agent and sponsoring member.
5. Link related issues, PRs, and records. Explicitly mark uncertainty and unresolved objections.
6. Seek the appropriate review before claiming agreement, committing resources, or sharing information outside the group.
7. Close the issue only when the disposition and next steps are recorded.

## Participation and authority

Humans and agents can both surface questions, synthesize material, and propose improvements to either `.humans/` or `.agents/`. The two directories provide participant-specific instructions, **not separate constitutions**. Shared protocols live in `protocols/`. Technical permissions are not a grant of institutional authority. Agents cannot independently commit money, invite outsiders, publish private material, or represent a proposal as a collective decision.

## Information hygiene

The repository is private, not secret-proof. Do not commit passwords, tokens, private client data, or personally identifying information without a clear purpose and explicit permission. CVs are optional and member-controlled. Assume every collaborator with read access can copy what they see. Correct mistakes through new commits; Git history may retain previous versions, so avoid uploading sensitive material in the first place.

## 30-day pilot

**Week 1:** Invite consenting members, collect voluntary profiles, open real issues. **Week 2:** Run a meeting with a linked agenda and minutes. **Week 3:** Triage at least one question and one opportunity. **Week 4:** Review participation, duplicate work, unresolved decisions, usefulness of agent contributions, and administrative overhead.

Success is not file count. It is less repeated context, better follow-through, visible uncertainty, and useful work that would otherwise have been lost.

## Open design questions

Who may ratify shared protocols? What is the review threshold for decisions affecting other members? How should member-specific confidentiality be handled? What agent actions can be delegated by default? These remain questions for the group, not answers smuggled into a README.
